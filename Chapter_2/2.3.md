## Topic 3: Router Architecture

Now we move to **Router Architecture — Functional Perspective + Hardware Perspective**.

# 1. Basic Router Architecture

From your PPT, a router has three major functional components:

```text
                 ┌──────────────────────┐
                 │   Routing Processor   │
                 │                      │
                 │ Routing protocols    │
                 │ Routing table        │
                 └──────────┬───────────┘
                            │
                            ↓
      ┌──────────────────────────────────────┐
      │          Switching Fabric            │
      │             / Backplane              │
      └───────────────┬──────────────────────┘
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
   ┌─────────────┐         ┌─────────────┐
   │ Input Line   │         │ Output Line │
   │ Card         │         │ Card        │
   │              │         │             │
   │ Ingress      │         │ Egress      │
   │ processing   │         │ processing  │
   └─────────────┘         └─────────────┘
```

The three major components are:

1. **Line Cards**
2. **Switching Fabric / Backplane**
3. **Routing Processor**

---

# 2. Line Cards

A **line card** is associated with a router interface and handles packets entering or leaving the router.

Your PPT says that the line card:

* parses packet/IP information
* makes forwarding decisions
* handles queueing
* may discard packets
* contains memory for packets waiting to be forwarded
* houses the port/network interface

Think of it as the router's **interface-level packet processing unit**.

---

# 3. Ingress vs Egress

Two important words:

### Ingress

Means:

> **Packet entering the router**

```text
Network
   ↓
[Ingress Line Card]
   ↓
Router
```

### Egress

Means:

> **Packet leaving the router**

```text
Router
   ↓
[Egress Line Card]
   ↓
Network
```

So:

```text
Ingress = IN
Egress  = OUT
```

This is a very common exam/MCQ concept.

---

# 4. Switching Fabric / Backplane

The switching fabric is the internal mechanism that transfers packets from the selected input/ingress line card to the appropriate output/egress line card.

```text
Ingress LC
    │
    ↓
┌───────────────────┐
│ Switching Fabric  │
│ / Backplane       │
└───────────────────┘
    │
    ↓
Egress LC
```

It is essentially the router's **internal packet transportation system**.

### Important:

The switching fabric does **not primarily decide the destination route**.

The forwarding logic determines the appropriate output.

The switching fabric then provides the internal path to that output.

---

# 5. Routing Processor

The routing processor is responsible for the router's **control-plane functions**.

It:

* runs routing protocols
* exchanges routing information with neighboring routers
* maintains routing information
* constructs/updates the routing table
* handles router configuration and management

For example, routing protocols may determine:

```text
Destination Network
        ↓
Best path
        ↓
Routing Table
        ↓
Forwarding Table
```

---

# 6. Very Important Distinction

You should remember:

| Component         | Main responsibility         |
| ----------------- | --------------------------- |
| Line Card         | Packet/interface processing |
| Switching Fabric  | Move packet internally      |
| Routing Processor | Routing/control functions   |

A common exam trap is:

> "The switching fabric calculates the best route."

❌ No.

The routing/control functions determine the route.

The switching fabric transfers packets between line cards.

# 8. Hardware Perspective

Your professor also gives another view:

> How is a router actually implemented using hardware?

The simplified architecture is:

```text
Network
   ↓
NIC
   ↓
PCI Bus
   ↓
Main Memory
   ↓
CPU
   ↓
Main Memory
   ↓
PCI Bus
   ↓
Output NIC
   ↓
Network
```

Let's understand it.

---

# 9. Step 1 — Packet Arrives at NIC

The packet first arrives at the router's network interface card.

```text
Network
   ↓
[NIC]
```

The NIC receives the packet from the physical network.

---

# 10. Step 2 — Packet Moves to Memory

The packet is transferred from the NIC toward main memory through the system bus, represented in your lecture by the **PCI bus**.

```text
NIC
 ↓
PCI Bus
 ↓
Memory
```

The bus bandwidth becomes important for router performance.

---

# 11. Step 3 — Packet Processing

The CPU performs processing such as:

* examining headers
* checksum/TTL processing
* destination address processing
* forwarding lookup
* determining the output interface

Conceptually:

```text
Memory
   ↓
CPU
   ↓
Packet processing
```

---

# 12. Step 4 — Packet Goes to Output NIC

After processing:

```text
Memory
   ↓
PCI Bus
   ↓
Output NIC
   ↓
Network
```

So the complete simplified process is:

```text
Input NIC
    ↓
Memory
    ↓
CPU
    ↓
Memory
    ↓
Output NIC
```

This is extremely important because it leads directly to the **Linux PC router performance numerical** in your next section.

---

# 13. Why Can This Architecture Be Slow?

Look at the packet path:

```text
NIC
 ↓
Memory
 ↓
CPU
 ↓
Memory
 ↓
NIC
```

The packet is being moved multiple times.

The bus is also shared by these transfers.

Therefore, even if the CPU is very fast, the **bus/memory transfer can become the bottleneck**.

This is exactly what your professor demonstrates using:

* PCI bandwidth = 2 Gbps
* CPU = 2 GHz
* 200 instructions
* packet/header size = 40 bytes

# 16. Important Conceptual Question

### Why is the routing processor not necessarily involved in every packet forwarding decision?

Because modern routers separate **control-plane** and **data-plane** operations.

The routing processor can calculate routes and maintain routing information, while the forwarding path uses the resulting forwarding information to process packets at high speed.

Conceptually:

```text
        CONTROL PLANE
              │
       Routing Processor
              │
        Routing Table
              ↓
       Forwarding Table
              │
              ↓
        DATA PLANE
              │
         Line Cards
              │
       Switching Fabric
              │
        Packet Forwarding
```

This separation is fundamental to high-performance routers.

# CS 606T — Router Architectures

## Topic 3: Router Architecture — Answers

### Q1. What are the three major functional components of a router?

The three major functional components are:

1. **Line Cards** — handle packet reception, forwarding-related processing, queueing, and transmission.
2. **Switching Fabric / Backplane** — transfers packets from ingress line cards to the appropriate egress line cards.
3. **Routing Processor** — implements routing protocols and maintains the routing information/routing table.

---

### Q2. What is the function of a line card?

A **line card** connects a router to a network interface and handles packet processing at that interface.

Its functions include:

* Receiving incoming packets.
* Parsing packet/IP headers.
* Performing forwarding-related processing.
* Maintaining packet buffers/queues.
* Deciding whether packets should be forwarded or discarded.
* Sending packets toward the appropriate output interface.

In short:

> **Line card = interface-level packet processing and buffering.**

---

### Q3. Differentiate between ingress and egress.

| Ingress                             | Egress                                   |
| ----------------------------------- | ---------------------------------------- |
| Packet entering the router          | Packet leaving the router                |
| Input side                          | Output side                              |
| Performs incoming packet processing | Performs outgoing packet processing      |
| Determines forwarding information   | Queues/schedules packet for transmission |

Simple way to remember:

$$
\boxed{\text{Ingress = IN}}
$$

$$
\boxed{\text{Egress = EXIT}}
$$

---

### Q4. What is a switching fabric?

A **switching fabric**, also called a **switching backplane**, is the internal mechanism of a router that transfers packets from an ingress line card to the appropriate egress line card.

```text
Ingress Line Card
       |
       ↓
Switching Fabric
       |
       ↓
Egress Line Card
```

Its main purpose is:

> **Fast internal transfer of packets between input and output interfaces.**

---

### Q5. What is the role of the routing processor?

The **routing processor** performs the router's control-plane functions.

Its major responsibilities include:

* Running routing protocols.
* Exchanging routing information with neighboring routers.
* Maintaining the routing table.
* Processing routing updates.
* Responding to topology changes.
* Performing router configuration and management functions.

Conceptually:

$$
\text{Routing Protocols}
\rightarrow
\text{Routing Table}
\rightarrow
\text{Forwarding Information}
$$

---

### Q6. Trace the journey of a packet through a router.

A simplified packet journey is:

```text
Incoming Network
       ↓
Ingress Line Card
       ↓
Header / Packet Processing
       ↓
Forwarding Table Lookup
       ↓
Switching Fabric
       ↓
Egress Line Card
       ↓
Queue / Scheduling
       ↓
Outgoing Network
```

### Explanation:

1. Packet arrives at the **ingress interface**.
2. The ingress line card examines the packet.
3. The destination address is used for forwarding lookup.
4. The appropriate output interface is determined.
5. The switching fabric transfers the packet internally.
6. The egress line card receives the packet.
7. The packet may be queued and scheduled.
8. The packet is transmitted through the output interface.

---

### Q7. Differentiate between the functional and hardware perspectives of router architecture.

### Functional perspective

Focuses on **what the router components do**:

* Line cards
* Switching fabric
* Routing processor

### Hardware perspective

Focuses on the physical processing path:

```text
Input NIC
    ↓
PCI Bus
    ↓
Main Memory
    ↓
CPU
    ↓
Main Memory
    ↓
PCI Bus
    ↓
Output NIC
```

| Functional Perspective       | Hardware Perspective              |
| ---------------------------- | --------------------------------- |
| Describes logical components | Describes physical implementation |
| Line cards                   | NICs                              |
| Switching fabric             | Internal bus/backplane            |
| Routing processor            | CPU                               |
| Packet buffers               | Main/interface memory             |

---

### Q8. Why can the PCI bus become a bottleneck in a PC-based router?

In the simplified PC-based router architecture, packets must be transferred through the bus.

A packet may follow:

```text
Input NIC
   ↓
PCI Bus
   ↓
Memory
   ↓
CPU
   ↓
Memory
   ↓
PCI Bus
   ↓
Output NIC
```

Therefore, the packet uses the bus multiple times.

Even if the CPU is very fast, the bus bandwidth may limit the rate at which packets can be transferred.

For example, your lecture considers:

$$
PCI\ bandwidth = 2\,Gbps
$$

while the resulting router throughput is approximately:

$$
760\,Mbps
$$

Thus:

> **The PCI bus can become the bottleneck because packet movement across the bus consumes significant processing time.**

---

### Q9. Why is the routing processor not required to perform the complete routing calculation for every incoming packet?

Because routing and forwarding are separated.

The routing processor performs relatively slower **control-plane** operations such as:

* Running routing protocols.
* Calculating routes.
* Maintaining routing information.

The resulting information is used to construct the **forwarding table**.

Then packet forwarding can happen rapidly using that forwarding information.

```text
        Routing Processor
               ↓
        Routing Algorithm
               ↓
         Routing Table
               ↓
       Forwarding Table
               ↓
      Fast Packet Forwarding
```

This separation prevents every packet from requiring a complete routing calculation.

---

### Q10. Differentiate between the control plane and data plane.

| Control Plane                           | Data Plane                          |
| --------------------------------------- | ----------------------------------- |
| Determines how traffic should be routed | Actually forwards packets           |
| Runs routing protocols                  | Performs packet forwarding          |
| Maintains routing information           | Uses forwarding table               |
| Handles topology changes                | Handles high-rate packet processing |
| Generally less time-critical per packet | Highly performance-critical         |

### Example

The control plane determines:

> "To reach network X, use interface 3."

The data plane then performs this operation for incoming packets:

> "Destination matches network X → send through interface 3."
