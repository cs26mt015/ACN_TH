# CS 606T — Router Architectures

## Topic 2: Forwarding Functions

Now we move to the next topic after **Routing vs Forwarding + Routing Table vs Forwarding Table**.

The key idea is:

> **A router receives a packet → checks it → modifies some fields → decides where it should go → possibly fragments it → sends it onward.**

---

# 1. What happens when a packet arrives?

Suppose a packet arrives at router R1:

```text
Host A
   |
   ↓
[Ingress Interface]
   |
   ↓
[Packet Processing]
   |
   ↓
[Forwarding Table Lookup]
   |
   ↓
[Output Interface]
   |
   ↓
Host B
```

The router performs several operations.

From your PPT, the important forwarding functions are:

1. IP Header Validation
2. Packet Lifetime Control
3. Checksum Restoration
4. Route Lookup
5. Fragmentation

And additional functions include:

6. Packet Classification
7. Packet Translation
8. Traffic Prioritization

Let's understand each.

---

# 2. IP Header Validation

When a packet arrives, the router first checks whether its IP header is valid.

For example, it checks:

* IP version
* Header length
* Header correctness
* Checksum

### Why?

The router should not forward a corrupted or malformed packet.

Conceptually:

```text
Incoming packet
      ↓
Is IP header valid?
      ↓
   YES     NO
    ↓       ↓
Continue   Drop
```

---

# 3. Packet Lifetime Control — TTL

This is extremely important.

Every IP packet has a field called:

> **TTL = Time To Live**

It prevents a packet from circulating forever in the network.

Suppose:

```text
A → R1 → R2 → R3 → B
```

The packet might initially have:

```text
TTL = 5
```

After R1:

```text
TTL = 4
```

After R2:

```text
TTL = 3
```

After R3:

```text
TTL = 2
```

So, approximately:

$$
TTL_{new}=TTL_{old}-1
$$

at each router hop.

---

# 4. Why do we need TTL?

Consider a routing loop:

```text
        ┌───────┐
        ↓       |
A → R1 → R2 → R3
     ↑           |
     └───────────┘
```

If there were no TTL, a packet caught in the loop could circulate indefinitely.

TTL provides a mechanism to eventually destroy it.

When TTL reaches zero, the router discards the packet and normally sends an ICMP Time Exceeded message back toward the source.

---

# 5. Checksum Restoration

There is an important connection here.

The router decrements TTL.

But TTL is part of the IP header.

Therefore, changing TTL changes the header contents.

So the IP header checksum must be updated/recomputed.

Conceptually:

```text
Original packet
TTL = 10
Checksum = C1

        ↓ Router

TTL = 9
Checksum = C2
```

Therefore:

> **TTL modification → IP header checksum must be updated.**

### Exam trap

A common mistake is saying:

> "The router changes TTL but checksum remains unchanged."

❌ Incorrect.

---

# 6. Route Lookup / Forwarding Lookup

Now the router needs to answer:

> **Where should this packet go next?**

The router examines the destination IP address.

For example:

```text
Destination IP = 192.168.5.20
```

The router performs a lookup in its forwarding table.

Example:

| Destination Prefix | Next Hop | Output Interface |
| ------------------ | -------- | ---------------- |
| 192.168.1.0/24     | R2       | 1                |
| 192.168.5.0/24     | R3       | 2                |
| 10.0.0.0/8         | R4       | 3                |

For:

```text
Destination = 192.168.5.20
```

the router finds:

```text
192.168.5.0/24
```

and sends the packet through:

```text
Output Interface = 2
```

---

# 7. Important: Routing Table vs Forwarding Table

Remember the previous topic.

### Routing process

Determines paths and produces:

```text
Routing Table
```

Then:

```text
Routing Table
      ↓
Forwarding Table
      ↓
Fast packet forwarding
```

The forwarding lookup must be extremely fast because routers can process huge numbers of packets per second.

---

# 8. Fragmentation

This is another important exam topic.

Suppose an incoming packet is:

```text
Packet size = 4000 bytes
```

but the outgoing link can carry only:

```text
MTU = 1500 bytes
```

The packet is too large for the outgoing link.

The router may need to divide it into smaller fragments.

```text
Original packet
┌───────────────────────────────┐
│          4000 bytes           │
└───────────────────────────────┘

              ↓

      Fragmentation

 ┌───────────┐ ┌───────────┐ ┌───────────┐
 │ Fragment1 │ │ Fragment2 │ │ Fragment3 │
 └───────────┘ └───────────┘ └───────────┘
```

Each fragment can then fit within the outgoing link's MTU.

---

# 9. Why does fragmentation occur?

Because:

$$
MTU_{outgoing} < Packet\ Size
$$

For example:

```text
Incoming packet = 4000 bytes
Outgoing MTU = 1500 bytes
```

Therefore:

```text
4000 > 1500
```

and fragmentation may be necessary.

---

# 10. Packet Classification

Modern routers don't always treat every packet identically.

They may classify packets based on information such as:

* Source IP
* Destination IP
* Source port
* Destination port
* Protocol
* Other packet fields

Example:

```text
Netflix traffic
      ↓
High priority

Background file transfer
      ↓
Lower priority
```

The classification allows the router to apply different policies.

---

# 11. Packet Translation — NAT

Your PPT gives the example of NAT.

Suppose many devices inside a home network use private addresses:

```text
192.168.1.10
192.168.1.11
192.168.1.12
```

They may share one public IP address:

```text
Public IP
203.x.x.x
```

The gateway/router performs **Network Address Translation (NAT)**.

Conceptually:

```text
Private Network
       |
       ↓
     Router
     NAT
       |
       ↓
Internet
```

The router translates addresses/ports so multiple internal hosts can communicate using shared public addressing.

---

# 12. Traffic Prioritization

Different applications may require different service levels.

For example:

```text
Voice/video
    ↓
Low delay required

Email
    ↓
Less delay-sensitive

Large backup
    ↓
Can tolerate delay
```

A router can therefore prioritize packets.

This is related to:

> **QoS — Quality of Service**

The router can use queues and scheduling policies to decide which packet should be transmitted first.

---

# 13. Put Everything Together

When a packet arrives:

```text
              PACKET ARRIVES
                    │
                    ↓
          IP Header Validation
                    │
                    ↓
              TTL Processing
                    │
                    ↓
          Checksum Update
                    │
                    ↓
          Destination Lookup
                    │

            Packet Classification

       ┌────────────┴────────────┐
```

Not every packet necessarily undergoes every possible operation; the exact processing depends on the router configuration, packet, protocol, and network conditions.

# CS 606T — Router Architectures

## Topic 2: Forwarding Functions — Answers

### Q1. What happens when an IP packet arrives at a router?

When an IP packet arrives at a router, the router performs several forwarding operations:

1. Validates the IP header.
2. Decrements the TTL value.
3. Updates/recomputes the IP header checksum.
4. Examines the destination IP address.
5. Performs a forwarding-table lookup.
6. Determines the appropriate output interface/next hop.
7. Performs additional functions such as classification, NAT, QoS, or fragmentation if required.
8. Queues and schedules the packet for transmission.
9. Sends the packet through the selected output interface.

---

### Q2. Why is TTL decremented at every router?

**TTL (Time To Live)** prevents packets from circulating indefinitely in the network due to routing loops.

At every router:

$$
TTL_{new}=TTL_{old}-1
$$

When the TTL expires, the router discards the packet and normally sends an **ICMP Time Exceeded** message to the sender.

**Example:**

```text
Source → R1 → R2 → R3

TTL = 5
       ↓
R1 → 4
R2 → 3
R3 → 2
```

---

### Q3. Why must the IP checksum be updated after TTL modification?

The TTL field is part of the IP header.

When the router changes:

$$
TTL: 10\rightarrow9
$$

the contents of the IP header have changed.

Therefore, the IP header checksum must also be updated so that the modified header can be validated correctly.

**Key point:**

> TTL changes → IP header changes → checksum must be updated.

---

### Q4. What happens when TTL becomes zero?

When the packet's TTL expires, the router **discards the packet** instead of forwarding it.

The router normally generates an:

> **ICMP Time Exceeded**

message and sends it toward the source.

This prevents packets caught in routing loops from remaining in the network indefinitely.

---

### Q5. What is fragmentation?

**Fragmentation** is the process of dividing a large IP packet into smaller packets called **fragments** so that they can be transmitted over a link whose MTU is smaller than the original packet.

For example:

```text
Packet = 4000 bytes
Outgoing MTU = 1500 bytes

4000 bytes
    ↓
┌─────────┐ ┌─────────┐ ┌─────────┐
│Fragment │ │Fragment │ │Fragment │
└─────────┘ └─────────┘ └─────────┘
```

The fragments can then travel across the smaller-MTU link.

---

### Q6. Why does a router perform fragmentation?

A router may need to fragment a packet when:

$$
Packet\ Size > Outgoing\ Link\ MTU
$$

For example:

$$
4000 > 1500
$$

Therefore, the original packet cannot fit into a single outgoing frame/packet transmission unit and fragmentation may be required, subject to the applicable IP fragmentation rules.

---

### Q7. What is MTU?

**MTU = Maximum Transmission Unit**

It is the maximum size of an IP packet that can be carried by a particular network link/interface without requiring fragmentation at that point.

For example:

```text
Ethernet MTU ≈ 1500 bytes
```

If an outgoing interface has an MTU of 1500 bytes and a packet is larger than that, the router must handle the MTU constraint appropriately.

### Important distinction:

**MTU ≠ bandwidth**

* MTU → maximum packet size
* Bandwidth → data transmission capacity per second

---

### Q8. Explain packet classification.

**Packet classification** means identifying packets according to specific packet-header fields and applying appropriate rules or policies.

A router may classify packets using:

* Source IP address
* Destination IP address
* Source port
* Destination port
* Protocol
* Other relevant fields

For example:

```text
Video traffic       → High priority
Voice traffic       → High priority
Email               → Normal priority
Background backup   → Low priority
```

Packet classification is commonly used for **QoS, filtering, security, and traffic management**.

---

### Q9. What is NAT and why is it performed by routers?

**NAT = Network Address Translation**

NAT allows private/internal addresses to be translated to public addresses when communicating with external networks.

For example:

```text
PC1 → 192.168.1.10 ─┐
PC2 → 192.168.1.11 ─┼→ Router/NAT → Internet
PC3 → 192.168.1.12 ─┘
                         |
                    Public IP
```

A router/gateway maintains the necessary translation state so that multiple internal hosts can communicate through shared public addressing.

NAT is commonly used at network boundaries, especially in IPv4 networks.

---

### Q10. How does traffic prioritization support QoS?

Traffic prioritization gives different packets different levels of service according to application or policy requirements.

For example:

| Traffic      | Priority |
| ------------ | -------- |
| Voice        | High     |
| Video        | High     |
| Web browsing | Normal   |
| Large backup | Low      |

The router can place packets into different queues and use a scheduling algorithm to determine which queue gets transmission service.

This helps provide QoS characteristics such as:

* lower delay for important traffic
* controlled bandwidth allocation
* reduced congestion impact
* differentiated service

---

# ⭐ 5 Very Important One-Line Answers

These are worth memorizing for MCQs/short answers:

**TTL:** Prevents packets from circulating indefinitely.

**Checksum:** Detects errors in the IP header; it must be updated when relevant header fields change.

**MTU:** Maximum packet size that can be transmitted over a particular link/interface without fragmentation at that point.

**Packet classification:** Identifying packets based on header/flow information to apply policies.

**NAT:** Translates network addresses (and commonly transport-layer ports) between address domains.

## 🔥 One Integrated Exam Question

**Question:** A packet arrives at a router with TTL = 1 and size = 2000 bytes. The outgoing interface has MTU = 1500 bytes. Explain what the router needs to consider.

**Answer:**

First, the router decrements:

$$
TTL=1\rightarrow0
$$

Since the TTL has expired, the router **discards the packet** and normally generates an ICMP Time Exceeded message.

Therefore, the packet is **not forwarded**, and the MTU/fragmentation issue does not result in transmission of this packet.

This is a good exam trap: **don't immediately start calculating fragments before checking whether the packet can even be forwarded.**
---

## 🔥 Tricky Question

Suppose:

```text
Packet size = 4000 bytes
Outgoing MTU = 1500 bytes
TTL = 5
```

The packet arrives at a router.

**Question:** What are the two independent issues the router has to deal with?

Think about it before looking at the answer.

### Answer

**Issue 1 — TTL**

The router decrements:

$$
5 \rightarrow 4
$$

and updates the IP header checksum.

**Issue 2 — MTU**

Since:

$$
4000 > 1500
$$

the packet may need fragmentation before being transmitted over the outgoing link.

So these are **two separate forwarding functions**:

```text
TTL processing
+
Fragmentation
```

---

### One subtle point to remember

Don't confuse:

**Routing** with **forwarding**.

> **Routing:** "What path should packets take?"

> **Forwarding:** "This packet has arrived; which interface should I send it through?"

That distinction is foundational for the rest of this chapter.
