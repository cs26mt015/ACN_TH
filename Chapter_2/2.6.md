# Topic 6: Crossbar Scheduling, HOL Blocking & PIM

We have already covered the architecture of a crossbar. Now let's go deeper into **how packets are actually scheduled**, why utilization becomes low, and how **Parallel Iterative Matching (PIM)** addresses the problem.

---

# 1. Why Do We Need Scheduling?

Consider a 4 × 4 crossbar:

```text
             Outputs
          O1  O2  O3  O4
          │   │   │   │
I1 ───────┼───┼───┼───┼
I2 ───────┼───┼───┼───┼
I3 ───────┼───┼───┼───┼
I4 ───────┼───┼───┼───┼
```

Suppose packets request:

```text
I1 → O1
I2 → O1
I3 → O2
I4 → O3
```

We have a conflict:

```text
I1 ──→ O1
I2 ──→ O1
```

Both cannot use O1 during the same timeslot.

Therefore, a **scheduler** must decide which connections are allowed.

---

# 2. What is a Match?

A **match** is a selected input-output pair.

For example:

```text
I1 → O1
I3 → O2
I4 → O3
```

is a valid match because:

* I1 is used once
* I3 is used once
* I4 is used once
* O1 is used once
* O2 is used once
* O3 is used once

So three packets can be transferred simultaneously.

---

# 3. What is a Maximal Matching?

A matching is **maximal** if you cannot add another valid input-output pair without violating the constraints.

Example:

```text
I1 → O1
I2 → O2
I3 → O3
```

If I4 and O4 are both available and:

```text
I4 → O4
```

is possible, then the previous matching wasn't maximal.

Add it:

```text
I1 → O1
I2 → O2
I3 → O3
I4 → O4
```

Now no additional pair can be added.

---

# 4. Maximum vs Maximal Matching

This is an important theoretical distinction.

### Maximum matching

A matching containing the **largest possible number of pairs**.

### Maximal matching

A matching to which **no additional pair can be added**.

Therefore:

$$
\boxed{\text{Maximum} \Rightarrow \text{Maximal}}
$$

but:

$$
\boxed{\text{Maximal} \not\Rightarrow \text{Maximum}}
$$

A maximal matching doesn't necessarily contain the maximum possible number of matches.

---

# 5. Example

Suppose requests are:

```text
I1 → O1
I1 → O2
I2 → O1
I2 → O2
```

One possible matching:

```text
I1 → O1
```

This is **not maximal**, because we can add:

```text
I2 → O2
```

So:

```text
I1 → O1
I2 → O2
```

is maximal and also maximum.

---

# 6. What is the Scheduler Trying to Achieve?

Ideally:

> Transfer as many packets as possible during every timeslot.

For an \(N\times N\) switch:

Maximum number of simultaneous transfers:

$$
\boxed{N}
$$

provided that there are enough packets and no conflicts.

For a 4 × 4 switch:

$$
\boxed{4}
$$

packets can potentially be transferred per timeslot.

---

# 7. Crossbar Utilization

Suppose a 4 × 4 crossbar operates for 3 timeslots.

Maximum possible transfers:

$$
4\times3=12
$$

Suppose only 8 packets are actually transferred.

Then:

$$
Utilization=
\frac{8}{12}\times100
$$

$$
\boxed{66.67\%}
$$

This is exactly the type of calculation your PPT illustrates.

---

# 8. Another Example

A 6 × 6 switch operates for 10 timeslots.

Maximum possible transfers:

$$
6\times10=60
$$

Suppose actual transfers:

$$
45
$$

Then:

$$
Utilization=
\frac{45}{60}\times100
$$

$$
\boxed{75\%}
$$

---

# 9. Why Isn't Utilization 100%?

There are several reasons:

* Multiple inputs request the same output.
* Some inputs don't have packets.
* Some outputs don't have packets destined for them.
* HOL blocking.
* Scheduling algorithm may not find the best possible matching.

The most important problem with simple input FIFO queues is:

$$
\boxed{\text{Head-of-Line Blocking}}
$$

---

# 10. HOL Blocking — Detailed Example

Consider two input queues:

```text
Input 1:
[P1 → O1] [P2 → O2]

Input 2:
[P3 → O1] [P4 → O3]
```

Suppose:

```text
O1 is requested by P1 and P3
```

Only one can win.

Assume:

```text
P1 → O1
```

is selected.

Then P3 waits.

But look at Input 2:

```text
[P3 → O1] [P4 → O3]
```

P4 wants O3.

O3 is free.

But P4 cannot move because P3 is at the head.

Therefore:

```text
P3 blocks P4
```

even though:

```text
O3 is available
```

This is HOL blocking.

---

# 11. The Core Idea of HOL Blocking

Remember this sentence for the exam:

> **A packet at the head of an input FIFO queue can prevent packets behind it from being transmitted even when their desired output is available.**

---

# 12. Why HOL Reduces Throughput

Suppose a switch has:

```text
I1 → O1
I2 → O1
I3 → O3
```

If I1 wins O1:

```text
I1 → O1 ✓
I2 → O1 ✗
I3 → O3 ✓
```

Fine.

But now suppose:

```text
I2:
[P → O1] [Q → O3]
```

P is blocked.

Therefore Q cannot use O3.

So:

```text
O3 = idle
```

even though there is a packet waiting for it.

This is wasted capacity.

---

# 13. Input Blocking vs Output Blocking

### Input blocking

An input cannot send a packet because another packet/constraint prevents it.

HOL is an important example.

### Output blocking

An output cannot accept multiple packets simultaneously.

Example:

```text
I1 ─┐
I2 ─┤
I3 ─┼──→ O1
I4 ─┘
```

All four want O1.

But only one can normally be served in a timeslot.

---

# 14. Solution 1 — Output Queueing

Instead of:

```text
Input → FIFO
```

we use:

```text
Output → Queue
```

Packets are transferred toward their destination output queues.

This removes the HOL problem because packets destined for different outputs don't wait behind each other at the input.

---

# 15. Output Queueing Numerical

Consider:

$$
N=4
$$

Each input operates at:

$$
1\,Gbps
$$

Worst case:

```text
I1 ─┐
I2 ─┤
I3 ─┼──→ O1
I4 ─┘
```

The output may receive:

$$
4\times1=4\,Gbps
$$

Therefore, the fabric may need approximately:

$$
\boxed{4\,Gbps}
$$

capacity.

General formula:

$$
\boxed{Fabric\ speed\approx N\times input\ rate}
$$

---

# 16. Solution 2 — Virtual Output Queueing

Instead of one FIFO queue at each input:

```text
Input 1:
[P1][P2][P3][P4]
```

create:

```text
Input 1:

VOQ1 → packets for O1
VOQ2 → packets for O2
VOQ3 → packets for O3
VOQ4 → packets for O4
```

Now packets for different outputs can be independently scheduled.

---

# 17. VOQ Example

Suppose:

```text
Input 1:

VOQ1: P1 → O1
VOQ2: P2 → O2

Input 2:

VOQ1: P3 → O1
VOQ3: P4 → O3
```

Suppose O1 is busy.

The scheduler can still select:

```text
P2 → O2
P4 → O3
```

instead of forcing them to wait behind packets destined for O1.

---

# 18. Number of VOQs

For an:

$$
N\times N
$$

switch:

Each input has:

$$
N
$$

VOQs.

There are N inputs.

Therefore:

$$
\boxed{N^2}
$$

total VOQs.

Example:

### 16 × 16 switch

$$
16^2=256
$$

VOQs.

---

# 19. The New Problem with VOQ

VOQ solves HOL blocking, but now the scheduler has a much harder problem.

It must examine:

$$
N^2
$$

queues and determine a conflict-free matching very quickly.

For a high-speed router, this decision may have to be made for every timeslot.

Therefore:

> **Scheduler complexity becomes the major challenge.**

This is where **PIM** becomes important.

---

# 20. Parallel Iterative Matching — PIM

PIM stands for:

$$
\boxed{\text{Parallel Iterative Matching}}
$$

Its objective is:

> Find a large set of conflict-free input-output matches quickly.

The key ideas are:

* Parallel
* Iterative
* Matching

---

# 21. Basic PIM Process

Conceptually:

```text
Requests
   ↓
Iteration 1
   ↓
Initial matches
   ↓
Iteration 2
   ↓
Additional/improved matches
   ↓
Iteration 3
   ↓
Better matching
   ↓
Final schedule
```

The scheduler performs multiple iterations within the scheduling period.

---

# 22. Why Not Simply Calculate the Perfect Matching?

Because routers operate at extremely high speed.

Imagine an enormous:

$$
N\times N
$$

switch.

Computing a mathematically optimal matching from scratch for every timeslot may be too expensive or slow.

PIM instead tries to:

> Quickly obtain a good/maximal matching.

This gives a practical trade-off between:

* scheduling quality
* scheduling speed

---

# 23. PIM — High-Level Operation

A simplified view:

### Step 1 — Request

Each input requests outputs for which it has packets.

Example:

```text
I1 → O1, O2
I2 → O1
I3 → O2, O3
```

### Step 2 — Grant

Outputs consider requests and grant one of them.

### Step 3 — Accept

Inputs choose among grants.

### Step 4 — Repeat

The process can be repeated for additional iterations.

The exact PIM algorithm contains randomized selection mechanisms to avoid persistent unfairness.

---

# 24. Why Multiple Iterations?

Imagine the first iteration produces:

```text
I1 → O1
I3 → O3
```

but:

```text
I2 → O2
```

wasn't selected.

Another iteration can examine remaining unmatched requests and potentially establish:

```text
I2 → O2
```

Thus more available capacity can be utilized.

---

# 25. PIM and Throughput

The goal is to approach:

$$
\boxed{100\%}
$$

throughput when traffic conditions permit.

But be careful:

> Don't write that PIM **always guarantees** 100% throughput.

The scheduling algorithm, traffic pattern, implementation, and timing constraints matter.

For an exam, say:

> PIM attempts to achieve a high-throughput, near-maximal matching at high speed.

---

# CS 606T — Switching Fabrics

## 20 Important Questions with Answers

### Q1. What is a Crossbar Switch?

**Answer:**
A crossbar switch is a switched-backplane architecture that provides direct connections between input and output ports through controllable crosspoints.

For an \(N\times N\) crossbar:

* \(N\) input ports
* \(N\) output ports
* \(N^2\) crosspoints

A scheduler determines which input-output connections are active during each timeslot.

---

### Q2. Why does an \(N\times N\) crossbar have \(N^2\) crosspoints?

**Answer:**

Each of the \(N\) inputs can potentially connect to each of the \(N\) outputs.

Therefore:

$$
N\times N=N^2
$$

Hence,

$$
\boxed{\text{Crosspoints}=N^2}
$$

Example:

For a \(4\times4\) crossbar:

$$
4^2=16
$$

crosspoints.

---

### Q3. What is a timeslot?

**Answer:**
A **timeslot** is a fixed time interval during which the scheduler establishes a particular set of input-output connections and packets are transferred across the switching fabric.

For example:

```text
Timeslot 1:
I1 → O1
I2 → O3

Timeslot 2:
I1 → O2
I3 → O4
```

The connections can change from one timeslot to another.

---

### Q4. Why is scheduling required in a crossbar?

**Answer:**
Scheduling is required because multiple inputs may request the same output, or an input may request multiple outputs simultaneously.

For example:

```text
I1 → O1
I2 → O1
```

Both cannot normally transmit to \(O1\) in the same timeslot.

The scheduler selects a **conflict-free set of input-output connections**.

Its goal is to maximize the number of simultaneous transfers while maintaining input/output constraints.

---

### Q5. What is a matching?

**Answer:**
A **matching** is a set of input-output connections in which:

* Each input is connected to at most one output.
* Each output receives from at most one input.

Example:

```text
I1 → O1
I2 → O3
I4 → O2
```

is a valid matching because no input or output is used more than once.

---

### Q6. Difference between maximal and maximum matching.

**Answer:**

| Maximum Matching                                | Maximal Matching               |
| ----------------------------------------------- | ------------------------------ |
| Contains the largest possible number of matches | Cannot add another valid match |
| Globally largest                                | Locally cannot be extended     |
| Always maximal                                  | May not be maximum             |

Important relationship:

$$
\boxed{\text{Maximum matching is always maximal}}
$$

but:

$$
\boxed{\text{Maximal matching is not necessarily maximum}}
$$

---

### Q7. Calculate crossbar utilization.

**Question:**
A \(4\times4\) crossbar operates for 3 timeslots. A maximum of 4 packets can be transferred per timeslot. If 8 packets are actually transferred, calculate utilization.

**Answer:**

Maximum possible transfers:

$$
4\times3=12
$$

Actual transfers:

$$
8
$$

Therefore:

$$
Utilization=
\frac{8}{12}\times100
$$

$$
\boxed{66.67\%}
$$

---

### Q8. Explain HOL blocking with an example.

**Answer:**
**Head-of-Line (HOL) blocking** occurs when a packet at the front of an input FIFO queue prevents packets behind it from being transmitted, even when those packets are destined for currently available outputs.

Example:

```text
Input 1:
[P1 → O1] [P2 → O2]
```

Suppose \(O1\) is busy.

Then \(P1\) cannot transmit.

Although \(O2\) is free, \(P2\) cannot move because it is behind \(P1\).

Therefore:

$$
\boxed{P1\text{ blocks }P2}
$$

This is HOL blocking.

---

### Q9. Why does input queueing suffer from HOL blocking?

**Answer:**
In input queueing, packets are commonly stored in a single FIFO queue at each input.

Because FIFO requires packets to be processed in order, a blocked head packet prevents packets behind it from being considered, even if their destination outputs are free.

Therefore:

$$
\boxed{\text{Input FIFO} \rightarrow \text{HOL Blocking}}
$$

---

### Q10. Why does output queueing eliminate HOL blocking?

**Answer:**
In output queueing, packets are placed into queues associated with their destination outputs.

Therefore, packets destined for different outputs do not have to wait behind one another in a single input FIFO queue.

Example:

```text
P1 → O1
P2 → O2
```

If \(O1\) is busy, \(P2\) can still enter the queue for \(O2\).

Thus:

$$
\boxed{\text{Output Queueing eliminates HOL blocking}}
$$

---

### Q11. Why does output queueing require an \(N\)-times faster fabric?

**Answer:**
Consider an \(N\times N\) switch.

In the worst case, all \(N\) input ports may simultaneously send packets to the same output.

```text
I1 ─┐
I2 ─┤
I3 ─┼──→ O1
... │
IN ─┘
```

If each input operates at \(R\) Gbps, the output may need to receive:

$$
N\times R
$$

Gbps.

Therefore, the switching fabric may need approximately:

$$
\boxed{N\times}
$$

the input line rate.

---

### Q12. What is Virtual Output Queueing (VOQ)?

**Answer:**
Virtual Output Queueing is a technique in which each input maintains a separate queue for each possible output.

For an \(N\times N\) switch, each input has \(N\) queues.

Example for a 4-output switch:

```text
Input 1:

VOQ1 → packets for O1
VOQ2 → packets for O2
VOQ3 → packets for O3
VOQ4 → packets for O4
```

The scheduler can independently select packets from these queues.

---

### Q13. Why does VOQ eliminate HOL blocking?

**Answer:**
In ordinary input FIFO queueing:

```text
[P1 → O1] [P2 → O2]
```

If \(O1\) is blocked, \(P2\) is also blocked.

With VOQ:

```text
VOQ1 → P1 → O1
VOQ2 → P2 → O2
```

If \(O1\) is busy, the scheduler can still select \(P2\) from VOQ2.

Therefore, packets destined for different outputs do not block one another.

$$
\boxed{\text{VOQ eliminates HOL blocking}}
$$

---

### Q14. How many VOQs are required for an \(N\times N\) switch?

**Answer:**

Each of the \(N\) inputs maintains \(N\) queues.

Therefore:

$$
N\times N=N^2
$$

Hence:

$$
\boxed{N^2\text{ VOQs}}
$$

Example:

For an \(8\times8\) switch:

$$
8^2=64
$$

VOQs.

For a \(32\times32\) switch:

$$
32^2=1024
$$

VOQs.

---

### Q15. What is the drawback of VOQ?

**Answer:**
The major drawback is **scheduler complexity**.

The scheduler has to examine many VOQs and select a conflict-free set of input-output connections within a very short timeslot.

For an \(N\times N\) switch:

$$
N^2
$$

VOQs exist.

As \(N\) increases, scheduling becomes increasingly complex.

Therefore:

$$
\boxed{\text{VOQ reduces HOL but increases scheduling complexity}}
$$

---

### Q16. What is PIM?

**Answer:**
PIM stands for:

$$
\boxed{\text{Parallel Iterative Matching}}
$$

It is a scheduling algorithm used in input-queued/VOQ-based switches to quickly find a large set of conflict-free input-output matches.

Its objective is to:

* maximize packet transfers per timeslot,
* reduce unused switching capacity,
* perform scheduling quickly.

---

### Q17. Why does PIM use multiple iterations?

**Answer:**
A single iteration may not find a sufficiently large matching.

Therefore, PIM repeats the matching process to find additional compatible input-output connections.

Conceptually:

```text
Requests
   ↓
Iteration 1
   ↓
Initial Matching
   ↓
Iteration 2
   ↓
Improved Matching
   ↓
...
   ↓
Final Matching
```

Multiple iterations allow the algorithm to approach a larger/maximal matching while still operating quickly.

---

### Q18. Compare Input Queueing, Output Queueing and VOQ.

**Answer:**

| Feature              | Input Queueing | Output Queueing                                    | VOQ                |
| -------------------- | -------------- | -------------------------------------------------- | ------------------ |
| Queue location       | Input          | Output                                             | Input              |
| HOL blocking         | Yes            | No                                                 | No                 |
| Fabric speed         | Normal         | Approximately \(N\times\) input rate in worst case | Normal-ish         |
| Number of queues     | \(N\)          | Output-dependent                                   | \(N^2\)            |
| Scheduler complexity | Relatively low | Different architecture                             | High               |
| Main problem         | HOL blocking   | Very high speed requirement                        | Complex scheduling |

The important progression is:

$$
\boxed{
Input\ Queue
\rightarrow
HOL
\rightarrow
VOQ
\rightarrow
Complex\ Scheduling
\rightarrow
PIM
}
$$
