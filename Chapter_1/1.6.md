# CS 606T — MPLS

## Label Distribution, Label Tables & Label Swapping

---

# 1. First: Why do we need MPLS?

In normal IP forwarding, a router receives a packet and examines the **destination IP address**.

For example:

```text
Destination IP:
10.20.30.40
       ↓
Router
       ↓
Routing table
       ↓
Longest Prefix Match
       ↓
Outgoing interface
```

This works, but MPLS introduces another approach:

```text
IP packet
   ↓
MPLS Label
   ↓
Label lookup
   ↓
Outgoing interface
```

So instead of repeatedly making forwarding decisions based on the full IP destination, MPLS routers can use a **short label**.

The fundamental idea is:

$$
\boxed{\text{IP routing determines the path; MPLS labels help forward along that path}}
$$

---

# 2. What is an MPLS Label?

An MPLS label is a short identifier attached to a packet.

Conceptually:

```text
┌───────────────────────────────┐
│ IP Header                     │
├───────────────────────────────┤
│ MPLS Label                    │
├───────────────────────────────┤
│ Data                          │
└───────────────────────────────┘
```

The label tells an MPLS router which forwarding action to perform.

For example:

```text
Incoming Label = 25

        ↓

MPLS forwarding table

        ↓

Outgoing Interface = 3
Outgoing Label = 41
```

So the router performs:

$$
\boxed{25\rightarrow41}
$$

This is called **label swapping**.

---

# 3. Very Important: Labels Have Local Scope

This is similar to the VCI concept we just studied.

Suppose:

```text
R1 → R2 → R3 → R4
```

The labels could be:

```text
R1 → R2 : Label 10
R2 → R3 : Label 25
R3 → R4 : Label 7
```

There is no requirement that every router use label 10.

Instead:

```text
R1:
10

R2:
25

R3:
7
```

Each label is meaningful within the local MPLS forwarding context.

Therefore:

$$
\boxed{\text{MPLS labels have local significance}}
$$

This is one of the similarities between:

**Virtual Circuit Switching** and **MPLS**.

---

# 4. What is an LER?

Your professor's PPT introduces:

$$
\boxed{\text{LER = Label Edge Router}}
$$

An LER is located at the **edge** of an MPLS network.

Example:

```text
                MPLS Network

          ┌─────────────────────┐
          │                     │
Internet → R1 → R2 → R3 → R4 → Internet
           ↑                 ↑
          LER               LER
```

The edge router receives traffic entering the MPLS domain and can classify it and impose an MPLS label.

---

# 5. What is an LSR?

Inside the MPLS network we have:

$$
\boxed{\text{LSR = Label Switch Router}}
$$

For example:

```text
        MPLS domain

LER        LSR       LSR       LER
 R1  ─────  R2  ───── R3  ───── R4
```

R2 and R3 forward packets primarily based on MPLS labels.

---

# 6. LER vs LSR

Remember this simple distinction:

| Device  | Role                                    |
| ------- | --------------------------------------- |
| **LER** | At MPLS edge                            |
| **LSR** | Inside MPLS network                     |
| **LER** | Adds/removes MPLS labels as appropriate |
| **LSR** | Performs label-based forwarding         |

Think:

```text
Outside → LER → LSR → LSR → LER → Outside
```

---

# 7. What is a Label Distribution Protocol?

Now we reach the important part from your PPT.

Your professor says:

> The router allocates a label for each prefix in its routing table and advertises both the label and the prefix to neighboring routers.

This requires routers to communicate label information.

One protocol used for this is:

$$
\boxed{\text{LDP = Label Distribution Protocol}}
$$

---

# 8. Why Do Routers Need to Distribute Labels?

Imagine:

```text
R1 → R2 → R3 → R4
```

Suppose the destination network is:

$$
10.10.0.0/16
$$

R3 needs to know what label should be used when forwarding traffic toward that destination.

So routers distribute information such as:

```text
Destination Prefix → Label
```

Conceptually:

```text
10.10.0.0/16 → Label 50
```

This information is shared with neighboring MPLS routers.

---

# 9. Important Distinction: IP Routing vs Label Distribution

Don't mix these two.

### IP routing

Answers:

> **Where should traffic go?**

For example:

```text
10.10.0.0/16
      ↓
Next hop = R3
```

### Label distribution

Answers:

> **Which label should be used for this forwarding context?**

For example:

```text
10.10.0.0/16
      ↓
Label = 50
```

Together they allow MPLS forwarding.

---

# 10. Let's Build a Network

Consider:

```text
          R1
          |
          |
          R2
          |
          |
          R3
          |
          |
          R4
```

Suppose:

* R1 = LER
* R2 = LSR
* R3 = LSR
* R4 = LER

And destination network is attached to R4:

```text
R1 → R2 → R3 → R4 → Destination
```

Suppose R4 advertises information about:

```text
Prefix = 192.168.50.0/24
```

and associates a label with it.

For learning purposes, suppose:

```text
192.168.50.0/24 → Label 30
```

---

# 11. Label Tables

An MPLS router maintains forwarding information that conceptually maps:

$$
\boxed{
\text{Incoming Label}
\rightarrow
\text{Outgoing Label + Interface}
}
$$

For example:

| Incoming Label | Outgoing Interface | Outgoing Label |
| -------------: | ------------------ | -------------: |
|             20 | R3                 |             30 |
|             25 | R4                 |             40 |
|             31 | R2                 |             15 |

This means:

```text
Incoming label 20
       ↓
     lookup
       ↓
Outgoing interface = R3
Outgoing label = 30
```

---

# 12. Label Swapping

Now let's see the actual forwarding.

Suppose R2 receives:

```text
Packet
Label = 20
```

R2 searches its MPLS forwarding table:

```text
Incoming Label 20
        ↓
Outgoing Interface = R3
Outgoing Label = 30
```

Therefore:

```text
20 → 30
```

The packet is sent to R3 with label 30.

---

# 13. At R3

Suppose R3's table says:

| Incoming Label | Outgoing Interface | Outgoing Label |
| -------------: | ------------------ | -------------: |
|             30 | R4                 |             45 |

R3 receives:

```text
Label = 30
```

Then:

```text
30 → 45
```

Packet moves toward R4.

---

# 14. Complete Label-Swapping Example

Let's put everything together:

```text
        Label 20       Label 30       Label 45
R1 ─────────────→ R2 ─────────────→ R3 ─────────────→ R4
                  │                  │
                swap               swap
               20→30              30→45
```

At R2:

$$
20\rightarrow30
$$

At R3:

$$
30\rightarrow45
$$

Therefore:

$$
\boxed{20\rightarrow30\rightarrow45}
$$

The packet is following the MPLS forwarding path.

---

# 15. What Exactly Does the Router Look At?

This is important.

Suppose R2 receives:

```text
Incoming interface = 1
Incoming label = 20
```

The router can use the incoming label and interface/context to find the appropriate forwarding entry.

Conceptually:

```text
(Incoming Interface, Incoming Label)
                ↓
          MPLS Table
                ↓
(Outgoing Interface, Outgoing Label)
```

This is very similar to what you learned for Virtual Circuit Switching:

```text
(Incoming Interface, Incoming VCI)
                ↓
             VC Table
                ↓
(Outgoing Interface, Outgoing VCI)
```

That's why MPLS is often taught alongside virtual circuits.

# 16. VC Switching vs MPLS

This comparison is extremely useful for your exam.

| Feature                            | Virtual Circuit    | MPLS                                                   |
| ---------------------------------- | ------------------ | ------------------------------------------------------ |
| Identifier                         | VCI                | Label                                                  |
| Identifier scope                   | Local              | Local                                                  |
| Forwarding                         | VCI lookup         | Label lookup                                           |
| Identifier changes at hops         | Yes                | Yes                                                    |
| Path can be established/engineered | Yes                | Yes                                                    |
| Uses forwarding tables             | Yes                | Yes                                                    |
| Exact label lookup                 | Yes                | Yes                                                    |
| Main purpose                       | Virtual connection | Label-based forwarding/traffic engineering/VPN support |

Conceptually:

```text
VC:

VCI 10
 ↓
Switch
 ↓
VCI 25
 ↓
Switch
 ↓
VCI 7


MPLS:

Label 10
 ↓
LSR
 ↓
Label 25
 ↓
LSR
 ↓
Label 7
```

Very similar mechanism.

# 17. Destination-Based Forwarding in MPLS

Your professor specifically included this phrase.

Let's understand it.

Suppose R1 has the following routing information:

| Prefix     | Next Hop |
| ---------- | -------- |
| 10.0.0.0/8 | R2       |
| 20.0.0.0/8 | R3       |
| 30.0.0.0/8 | R4       |

MPLS can associate labels with these forwarding destinations/prefixes.

Conceptually:

| Prefix     | Label |
| ---------- | ----: |
| 10.0.0.0/8 |    15 |
| 20.0.0.0/8 |    25 |
| 30.0.0.0/8 |    35 |

The label is then used for forwarding within the MPLS domain.

# 18. Why Does the Label Need to Change?

This is a very common question.

Why not simply assign:

```text
Destination → Label 100
```

and keep label 100 throughout the entire network?

Because MPLS labels have **local significance**.

Different routers can assign labels independently.

For example:

```text
R1 → R2
Label 10

R2 → R3
Label 50

R3 → R4
Label 7
```

Therefore each router performs a local mapping:

$$
\boxed{10\rightarrow50\rightarrow7}
$$

This is **label swapping**.

---

# 19. Explicit Routing

Now let's connect this with another bullet in your PPT.

Suppose the network looks like:

```text
             R3 ─── R6
            /         \
R1 ────────              R7
            \           /
             R4 ─ R5
```

There may be multiple possible routes.

For traffic:

```text
R1 → R7
```

we might want:

$$
R1\rightarrow R3\rightarrow R6\rightarrow R7
$$

while another flow:

$$
R2\rightarrow R7
$$

might use:

$$
R2\rightarrow R3\rightarrow R4\rightarrow R5\rightarrow R7
$$

MPLS can support these **explicitly engineered paths**.

---

# 20. Why Is This Useful?

Because normal IP routing might select a different path.

For example:

```text
Normal IP:
R1 → R2 → R4 → R7
```

But network engineering might want:

```text
MPLS:
R1 → R3 → R6 → R7
```

because of considerations such as:

* traffic distribution
* capacity
* congestion
* administrative policy
* QoS requirements

The important exam phrase is:

$$
\boxed{\text{MPLS supports explicit routing / traffic engineering}}
$$

# 21. Complete MPLS Flow

Now combine everything.

### Step 1 — IP routing information exists

Routers learn destination prefixes.

```text
Prefix → next hop
```

### Step 2 — Labels are assigned

A router associates labels with forwarding destinations.

```text
Prefix → Label
```

### Step 3 — Labels are distributed

Routers communicate label information with neighboring routers.

```text
LDP
 ↓
Label information
```

### Step 4 — MPLS forwarding begins

A packet enters through an LER.

```text
IP packet
   ↓
LER
   ↓
MPLS label imposed
```

### Step 5 — LSRs forward by label

```text
Label 10
   ↓
LSR
   ↓
Label 25
   ↓
LSR
   ↓
Label 40
```

### Step 6 — Packet exits MPLS domain

At the edge:

```text
LSR → LER → destination
```

The MPLS label is removed as appropriate and normal IP forwarding can continue.

# 24. Tricky Conceptual Question

### Question:

> If MPLS labels are locally significant, can two different links use the same label number?

### Answer:

**Yes.**

For example:

```text
R1 → R2 : Label 10

R3 → R4 : Label 10
```

This is not inherently a conflict because the labels have different local contexts.

The important point is:

$$
\boxed{\text{Label value alone does not imply global uniqueness}}
$$

---

# 25. Another Tricky Question

### Q:

> Does MPLS eliminate IP routing?

### Answer:

**No.**

MPLS works with routing information and can use IP routing information to establish forwarding state.

A simplified view is:

```text
IP routing
    ↓
Determine destination/reachability
    ↓
MPLS label distribution / forwarding state
    ↓
Label-based forwarding
```

So MPLS is **not simply a replacement for IP routing**.
