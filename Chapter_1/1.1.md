# Chapter 1 — Introduction & Switching Techniques

## Part 1: Why do we need Internetworking?

Let's start with the fundamental problem your professor mentioned:

> **"Not all networks are directly connected."**

Imagine two computers:

```text
Computer A ───────────── Computer B
```

A point-to-point link works perfectly here.

But now imagine thousands or millions of computers:

```text
A ── B
│    │
C ── D ── E
     │
     F ── G ── H
```

We cannot practically create a direct physical link between every pair of hosts.

### Why?

Because different networks have different limitations.

### 1. Point-to-point link

A point-to-point link connects only **two devices**.

For example:

```text
A ================= B
```

If we have 1000 computers and want every computer directly connected to every other computer, the number of links becomes enormous.

The number of possible direct connections is:

$$
\frac{n(n-1)}{2}
$$

For \(n=1000\):

$$
\frac{1000(999)}{2}=499,500
$$

Clearly, this doesn't scale.

---

### 2. Ethernet limitations

A local Ethernet network can connect many hosts, but it still has practical limitations in size, bandwidth, and physical/network architecture.

So we can't simply keep extending one Ethernet network indefinitely.

---

### 3. Wireless limitations

Wireless communication has another problem:

> **Radio signals have limited range.**

For example:

```text
        Wireless range
       <------------>

          AP
       /  |  \
      /   |   \
     A    B    C
```

A device outside the radio range cannot directly communicate with the access point.

---

# The Solution: Internetworking

Instead of trying to create one gigantic network, we connect **multiple smaller networks together**.

For example:

```text
 Network A          Network B          Network C

 A ─ B ─ C          D ─ E ─ F          G ─ H
      │                   │                │
      └─── Switch ───── Router ─────── Router
```

This idea is called:

> **Internetworking**

### Definition

**Internetworking is the process of connecting different networks and network technologies so that they can communicate and operate as a larger interconnected network.**

The Internet is the most important example.

---

# Part 2: Switches and Routers

Now we have a problem:

> If networks are separate, what device connects them?

Your professor introduces two important devices:

### Switch

A **switch** primarily connects devices/networks of the same or compatible link technology and forwards traffic toward the appropriate output.

Example:

```text
        Host A
          │
          │
Host B ─ Switch ─ Host C
          │
          │
        Host D
```

A switch receives a packet on one input and determines the appropriate output.

---

### Router

A **router** connects different networks and forwards packets between them.

Example:

```text
Network A                    Network B

A ─ B ─ C                    X ─ Y ─ Z
      │                          │
      └────── Router ────────────┘
```

Think of it this way:

> **Switch → mainly connects nodes within a network/link technology**

> **Router → connects different networks**

Don't memorize this as an absolute rule for every modern device, but it is the conceptual distinction your introductory material is establishing.

---

# Part 3: What exactly does a switch do?

Your professor gives this important definition:

> A switch is a **multi-input, multi-output device** that transfers packets from an input to one or more outputs.

Let's visualize it.

```text
                Output 1
                   ↑
                   │
Input 1 ────┐      │
Input 2 ────┤   SWITCH ──── Output 2
Input 3 ────┤      │
Input 4 ────┘      ↓
                Output 3
```

Suppose a packet arrives:

```text
Packet
+-----------------------+
| Destination = Host D  |
| Data                  |
+-----------------------+
```

The switch needs to answer:

> **"Which output should I send this packet to?"**

That's the fundamental problem of **network switching**.

---

# Part 4: How does a switch know where to send a packet?

This is one of the most important concepts in this chapter.

The switch examines information in the **packet header**.

Simplified:

```text
+-------------------------+
| Header                  |
| Destination information |
+-------------------------+
| Data                    |
+-------------------------+
```

The identifier in the header is used to make the forwarding decision.

The switch then consults some form of **forwarding table**.

For example:

| Destination | Output |
| ----------- | ------ |
| A           | 1      |
| B           | 2      |
| C           | 3      |
| D           | 4      |

Suppose:

```text
Destination = C
```

The switch looks up:

```text
C → Output 3
```

and forwards the packet there.

---

# Part 5: Two Fundamental Approaches

Now we reach the central concept of your chapter.

There are two fundamental ways of forwarding traffic:

```text
                    Network Switching
                          │
             ┌────────────┴────────────┐
             │                         │
      Connectionless            Connection-oriented
             │                         │
      Packet/Datagram            Circuit/VC
       Switching                  Switching
```

### Approach 1 — Connectionless

Each packet contains enough information to independently determine where it should go.

This is:

> **Datagram / Packet Switching**

### Approach 2 — Connection-oriented

A connection/path is established before data transfer.

This leads to:

> **Circuit Switching**

and, in packet networks:

> **Virtual Circuit Switching**

---

# Part 6: Packet / Datagram Switching

This is our first switching technique.

The fundamental idea is extremely simple:

> **Every packet carries the destination address, and each packet is forwarded independently.**

Consider:

```text
A → S1 → S2 → S3 → B
```

Suppose A wants to send three packets:

```text
P1
P2
P3
```

Each packet contains something like:

```text
+-----------------------+
| Destination = B       |
+-----------------------+
| Data                  |
+-----------------------+
```

The network doesn't necessarily establish a dedicated path first.

Each switch makes its forwarding decision based on the packet.

---

## Example

Suppose:

```text
        S2
       /  \
      /    \
A → S1      S4 → B
      \    /
       \  /
        S3
```

Initially:

```text
P1 → S1 → S2 → S4 → B
```

But if the forwarding information changes, another packet might travel:

```text
P2 → S1 → S3 → S4 → B
```

So:

$$
P_1 \neq P_2 \text{ necessarily follow the same path}
$$

This is a **very important characteristic** of datagram switching.

---

# Part 7: Forwarding Table

How does S1 know where to send the packet?

It has a forwarding table.

Example:

| Destination | Next hop |
| ----------- | -------- |
| B           | S2       |
| C           | S3       |
| D           | S4       |

Packet:

```text
Destination = B
```

S1 checks:

```text
B → S2
```

So:

```text
S1 → S2
```

Then S2 performs its own lookup.

This continues until the packet reaches the destination.

---

# Part 8: Why are forwarding tables difficult?

This is another point directly from your professor's slides.

Imagine a tiny network:

```text
A ─ B ─ C
    │
    D
```

Easy.

But imagine the Internet:

```text
          ┌───────┐
      ┌───┤ Router├───┐
      │   └───────┘   │
      │       │       │
 ┌────┴───┐   │   ┌───┴────┐
 │ Router │───┘   │ Router │
 └────────┘       └────────┘
      │               │
     ...             ...
```

Now there are huge numbers of destinations and paths.

Additionally, topology can change:

```text
Before:

A → B → C → D

After:

A → B → X → D
```

Therefore, forwarding information must adapt to network changes.

This is why routing and forwarding become major topics in advanced computer networks.

# Part 9: Store-and-Forward

Your professor explicitly mentions:

> **Store and forward the packets**

What does this mean?

Suppose:

```text
A → S1 → S2 → B
```

A packet arrives at S1.

S1 doesn't simply magically teleport it to S2.

Conceptually:

### Step 1

Receive the packet.

```text
A ──→ [S1]
```

### Step 2

Store/buffer the packet.

```text
[S1]
┌─────────────┐
│ Packet      │
│ in buffer   │
└─────────────┘
```

### Step 3

Transmit it on the outgoing link.

```text
[S1] ─────────→ S2
```

This introduces **transmission delay** at each hop and potentially **queuing delay** if the output link is busy.

---

# Part 10: Best-Effort Delivery

Your professor also says:

> **Best effort delivery**

This means the network attempts to deliver the packet, but the basic packet-switching service does not necessarily guarantee:

* delivery
* fixed delay
* bandwidth
* absence of congestion
* fixed path

For example:

```text
A → R1 → R2 → B
       X
    congestion
```

The packet may experience delay or potentially be dropped depending on the network.

Therefore:

> **Best effort ≠ guaranteed delivery**

# Part 11: Important Characteristics of Datagram Switching

You should remember these six points:

### 1. Connectionless

No dedicated connection is established before sending each packet.

### 2. Destination address in every packet

Each packet contains the information needed for forwarding.

### 3. Independent forwarding

Each packet is treated independently.

### 4. Packets can take different paths

```text
P1 → Path A
P2 → Path B
P3 → Path A
```

### 5. Store-and-forward

Routers/switches receive and forward packets.

### 6. Best effort

The network does not inherently guarantee fixed delivery characteristics.

### Q1. Why can't we simply connect every computer directly to every other computer in a global network?

**Answer:**

A point-to-point link connects only two devices. If every computer had to be directly connected to every other computer, the number of links would grow rapidly.

For \(n\) devices, the number of direct links required would be:

$$
\frac{n(n-1)}{2}
$$

For example, with 1,000 devices:

$$
\frac{1000(999)}{2}=499,500
$$

Therefore, directly connecting every device is **expensive, complex, and not scalable**.

Instead, networks use **switches and routers to interconnect smaller networks**, which leads to the concept of **internetworking**.

**Key point:**

> Directly connecting every host does not scale; intermediate networking devices allow large networks to be built efficiently.

---

### Q2. What is the fundamental purpose of internetworking?

**Answer:**

**Internetworking** is the process of connecting different networks and network technologies so that they can communicate with each other and operate as one larger interconnected network.

For example:

```text
Network A ── Router ── Network B ── Router ── Network C
```

The fundamental purpose is to enable communication between hosts that belong to **different networks**.

**Exam definition:**

> Internetworking enables multiple heterogeneous networks to be interconnected to form a large-scale network such as the Internet.

---

### Q3. A packet arrives at a router with `Destination = X`. What information does the router use to determine where to forward it?

**Answer:**

The router examines the **destination information in the packet header** and consults its **forwarding table/routing table** to determine the appropriate next hop or output interface.

For example:

| Destination | Next Hop |
| ----------- | -------- |
| X           | R3       |
| Y           | R5       |
| Z           | R2       |

If:

```text
Destination = X
```

the router performs a lookup:

```text
X → R3
```

and forwards the packet toward R3.

**Key point:**

> The packet header provides the destination information, while the forwarding table determines the appropriate outgoing path/interface.

---

### Q4. In datagram switching, if packets P1 and P2 are sent from A to B, must they follow the same path?

**Answer:**

**No.**

In datagram/packet switching, every packet is forwarded **independently**.

Therefore:

```text
P1: A → R1 → R2 → B

P2: A → R1 → R3 → B
```

is possible.

This can happen because forwarding decisions may change due to:

* routing-table changes
* network failures
* congestion
* changing network conditions

Consequently, packets can potentially arrive at the destination through **different paths and at different times**.

**Important:** Because packets may follow different paths, they may also arrive **out of order**.

---

### Q5. What does store-and-forward mean?

**Answer:**

**Store-and-forward** means that a switch or router first **receives the packet and stores/buffers it**, and then forwards it through the appropriate outgoing link.

For example:

```text
A ──→ R1 ──→ R2 ──→ B
```

At R1:

```text
1. Receive packet
       ↓
2. Store/buffer packet
       ↓
3. Determine output
       ↓
4. Transmit packet to R2
```

The packet therefore has to be received before it can be transmitted onto the next link.

**Consequence:**
Store-and-forward introduces **transmission delay at each hop** and potentially **queuing delay** if the outgoing link is busy.

---

### Q6. What does best-effort delivery mean?

**Answer:**

**Best-effort delivery** means that the network attempts to deliver packets to their destination but does not inherently guarantee successful delivery or fixed performance.

It does not necessarily guarantee:

* delivery
* fixed delay
* fixed bandwidth
* no packet loss
* no congestion
* a fixed path

For example:

```text
A → R1 → R2 → B
          ↑
       congestion
```

Congestion can cause packets to experience additional delay or potentially be dropped.

**Exam definition:**

> Best-effort delivery provides an attempt to deliver packets without guaranteeing delivery, delay, bandwidth, or other performance characteristics.

---

### Q7. Is this possible in datagram switching?

```text
P1: A → R1 → R2 → B

P2: A → R1 → R3 → B
```

**Answer:**

**Yes, this is possible in datagram switching.**

Datagram switching is **connectionless**, and each packet is forwarded independently.

Therefore:

```text
P1 → R2
P2 → R3
```

can occur if the forwarding decisions at R1 differ for the two packets.

For example, the forwarding information could change between the arrival of P1 and P2.

### Important consequence

The packets may:

* follow different paths
* experience different delays
* arrive out of order

For example:

```text
P1 sent first ───────────────→ arrives at 20 ms

P2 sent second ───────→ arrives at 10 ms
```

So P2 could potentially arrive before P1.

**This is a very important characteristic of datagram switching.**

---

### Q8. What is the fundamental difference between connectionless and connection-oriented switching?

**Answer:**

The fundamental difference is **whether a connection/path is established before data transmission**.

| Connectionless                                | Connection-oriented                                       |
| --------------------------------------------- | --------------------------------------------------------- |
| No connection setup required                  | Connection/path is established first                      |
| Each packet is forwarded independently        | Packets follow an established logical/physical connection |
| Destination information is carried in packets | Connection/VC identifier can be used after setup          |
| Packets may take different paths              | Packets generally follow the established path             |
| Example: Datagram switching                   | Examples: Circuit switching, Virtual Circuit switching    |

### Simple analogy

**Connectionless:**

> "Here is the destination. Figure out how to get there."

**Connection-oriented:**

> "First establish a route between us. Then send the data through that established connection."
