# CS 606T — Chapter 1

## Part 2: Circuit Switching

Now we move from **connectionless packet switching** to **connection-oriented switching**.

The key idea is:

> **Before sending data, establish a dedicated path between the source and destination.**

---

# 1. Why do we need Circuit Switching?

Consider two hosts:

```text
A ── R1 ── R2 ── R3 ── B
```

With **datagram switching**, every packet can independently make forwarding decisions.

Circuit switching takes a different approach.

Before transmitting the actual data:

```text
A ── R1 ── R2 ── R3 ── B
      ═════════════════
       Dedicated path
```

A connection is first established.

Once the circuit is established, data can flow through that circuit.

---

# 2. Basic Working of Circuit Switching

Circuit switching generally has **three phases**:

```text
       Circuit Switching
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
   Setup   Data      Teardown
            Transfer
```

### Phase 1 — Circuit Setup

A requests communication with B.

```text
A → R1 → R2 → R3 → B
```

The network establishes a path.

For example:

```text
A ── R1 ── R2 ── R3 ── B
     ═════════════════
       Circuit
```

Resources are allocated along this path.

---

### Phase 2 — Data Transfer

Now A sends data:

```text
A ═══> R1 ═══> R2 ═══> R3 ═══> B
```

The established circuit is used for the communication.

---

### Phase 3 — Circuit Teardown

When communication finishes, the circuit is released.

```text
Circuit established
       ↓
Data transfer
       ↓
Circuit released
```

The resources can then be used by other connections.

---

# 3. The Most Important Idea: Dedicated Resources

This is what makes circuit switching fundamentally different from datagram switching.

Suppose a link has:

$$
10\text{ Mbps}
$$

A circuit might reserve part of this capacity for a particular communication.

Conceptually:

```text
10 Mbps link

┌──────────────────────────────┐
│ A → B │ C → D │ E → F │ ... │
└──────────────────────────────┘
```

Resources are allocated to established circuits.

Depending on the circuit-switched system, this can involve:

* bandwidth
* transmission capacity
* switching resources

The important idea is:

> **Resources are reserved for the duration of the circuit.**

---

# 4. Why is it called a "Circuit"?

Because the network creates a logical/physical communication path that behaves like a dedicated circuit between the communicating endpoints.

Think about a traditional telephone call.

When you call someone:

```text
You → telephone network → Other person
```

The network establishes the connection first.

Then you talk.

When the call ends, the connection is released.

That's the classic circuit-switching model.

---

# 5. Example

Suppose:

```text
A ── S1 ── S2 ── S3 ── B
```

A wants to communicate with B.

### Step 1: Setup

The network establishes:

```text
A → S1 → S2 → S3 → B
```

and reserves resources.

### Step 2: Data

Now:

```text
A → DATA → S1 → DATA → S2 → DATA → S3 → DATA → B
```

The path remains associated with this communication.

### Step 3: Teardown

When finished:

```text
A → release → network
```

The reserved resources are released.

---

# 6. Circuit Switching vs Datagram Switching

This is one of the **most important comparisons for your exam**.

| Feature                           | Circuit Switching                     | Datagram Switching           |
| --------------------------------- | ------------------------------------- | ---------------------------- |
| Connection                        | Connection-oriented                   | Connectionless               |
| Setup                             | Required                              | Not required                 |
| Path                              | Established before data               | Determined independently     |
| Resource reservation              | Yes                                   | Generally no                 |
| Packet forwarding                 | Along established circuit             | Independent                  |
| Path changes during communication | Generally no                          | Possible                     |
| Delay                             | More predictable after setup          | Can vary                     |
| Congestion                        | Can prevent setup/resource allocation | Can cause queuing/loss       |
| Resource utilization              | Can be inefficient for bursty traffic | Efficient for bursty traffic |
| Example                           | Traditional telephone network         | IP network                   |

---

# 7. The Big Advantage: Predictable Performance

Once the circuit is established and resources are reserved, the communication can have more predictable performance.

Suppose:

```text
A ═══════════════════ B
       dedicated
       resources
```

Other users cannot simply take the resources allocated to that circuit.

This makes circuit switching suitable for applications requiring relatively predictable continuous communication.

Your professor's surgical-robot example is based on this idea.

---

# 8. But There Is a Major Disadvantage

Consider this situation:

```text
A ═══════════════════ B
       circuit
```

Suppose A sends data for only 1 second and then remains silent for 30 seconds.

The circuit may still remain reserved during that period.

```text
Time →

Data:       ███
Idle:          ─────────────────
Resource:    RESERVED
```

The reserved capacity isn't necessarily available for other users.

This is **inefficient for bursty traffic**.

---

# 9. Why Packet Switching Handles Bursty Traffic Better

Imagine an online shopping website.

```text
User 1: ████────────────████
User 2: ──██───────────────
User 3: █████──────████─────
```

Traffic is not continuous.

Packet switching allows network resources to be statistically shared:

```text
Shared link
────────────────────────────
 User 1 ──┐
 User 2 ──┼──→ Shared capacity
 User 3 ──┘
────────────────────────────
```

When one user isn't transmitting, other users can use the capacity.

Therefore:

> **Packet switching is generally well suited to bursty data traffic.**

---

# 10. Circuit Switching Has Setup Delay

This is important for numerical problems.

Before data can be transmitted:

```text
Setup
  ↓
Data transmission
  ↓
Teardown
```

Suppose setup takes:

$$
50\text{ ms}
$$

Then the sender cannot start normal data transmission until the circuit setup phase is completed.

Therefore total time includes setup time.

---

# 11. Transmission Delay vs Propagation Delay

Your professor's numerical question uses these concepts.

### Transmission Delay

Time required to put all bits of a packet/file onto the link.

$$
\boxed{T_{trans}=\frac{L}{R}}
$$

where:

* \(L\) = number of bits
* \(R\) = transmission rate in bits/sec

Example:

File:

$$
5\text{ MB}
$$

Bandwidth:

$$
10\text{ Mbps}
$$

Using the professor's decimal convention:

$$
5\text{ MB}=5\times10^6\text{ bytes}
$$

Therefore:

$$
5\times10^6\times8
=40\times10^6\text{ bits}
$$

Then:

$$
T_{trans}
=
\frac{40\times10^6}{10\times10^6}
=4s
$$

---

### Propagation Delay

Time required for the signal to physically travel through the link.

$$
\boxed{T_{prop}=\frac{d}{v}}
$$

where:

* \(d\) = distance
* \(v\) = propagation speed

For the professor's example:

$$
d=2000\text{ km}
$$

$$
v=200000\text{ km/s}
$$

Therefore:

$$
T_{prop}
=
\frac{2000}{200000}
=
0.01s
$$

$$
=10ms
$$

---

# 12. Professor's Circuit-Switching Numerical

Given:

$$
R=10Mbps
$$

$$
d=2000km
$$

$$
v=200000km/s
$$

$$
Setup=50ms
$$

$$
File=5MB
$$

### Step 1 — Setup

$$
T_{setup}=0.05s
$$

### Step 2 — Propagation

$$
T_{prop}=\frac{2000}{200000}
=0.01s
$$

### Step 3 — Transmission

$$
5MB=40\times10^6bits
$$

$$
T_{trans}
=
\frac{40\times10^6}{10\times10^6}
=4s
$$

### Total

Under the simplified model used in the PPT:

$$
T_{total}
=
T_{setup}+T_{prop}+T_{trans}
$$

$$
=0.05+0.01+4
$$

$$
\boxed{T_{total}=4.06s}
$$

# 13. A Very Important Conceptual Trap

Don't confuse:

### Transmission delay

> How long does it take to **push the bits onto the link?**

with:

### Propagation delay

> How long does it take for the **signal to travel across the link?**

Imagine a 2,000 km cable.

```text
Sender                                  Receiver
  A                                        B
  │========================================│
        2000 km
```

If you're transmitting a huge file:

**Transmission delay** depends on:

$$
\frac{\text{data size}}{\text{bandwidth}}
$$

while **propagation delay** depends on:

$$
\frac{\text{distance}}{\text{propagation speed}}
$$

Increasing file size affects transmission delay, **not propagation delay**.

Increasing distance affects propagation delay, **not transmission delay**.

---

# 14. When Is Circuit Switching Useful?

Conceptually, circuit switching is attractive when communication is:

* continuous
* long-lived
* relatively predictable
* sensitive to variation in network performance

Classic example:

> **Traditional telephone calls**

Your professor's example:

> **Remote surgical robot**

is intended to illustrate the need for predictable communication characteristics.

However, remember that a real remote-surgery system would require much more than simply choosing circuit switching; the scenario is an educational illustration of the networking property.

---

# 15. Circuit Switching — Exam Definition

Memorize the **concept**, not just the sentence:

> **Circuit switching is a connection-oriented switching technique in which a dedicated communication path and associated resources are established between the source and destination before data transmission. The resources remain allocated for the duration of the connection and are released when the communication ends.**

# CS 606T — Circuit Switching: Answers

### Q1. What are the three phases of circuit switching?

**Answer:**

Circuit switching has three main phases:

1. **Circuit Setup**
2. **Data Transfer**
3. **Circuit Teardown**

```text
Setup
  ↓
Data Transfer
  ↓
Teardown
```

During **setup**, a path and required resources are established.

During **data transfer**, the actual information is transmitted over the established circuit.

During **teardown**, the circuit is released and its resources become available for other connections.

---

### Q2. Why does circuit switching require a setup phase?

**Answer:**

Circuit switching requires setup because the network must first establish a **dedicated communication path** and allocate the required resources before data transmission begins.

For example:

```text
A ── R1 ── R2 ── R3 ── B
     ═════════════════
       Established
        circuit
```

The setup phase determines the path and reserves resources along it.

Only after successful setup can the source begin normal data transmission.

**Exam point:**

> Setup introduces an initial delay, but after setup the communication can have more predictable performance.

---

### Q3. Why can circuit switching waste bandwidth when traffic is bursty?

**Answer:**

In circuit switching, resources are reserved for the connection even when the user is temporarily not transmitting data.

For example:

```text
Time →

Data:      ████───────████
Circuit:   ███████████████
           ↑
      Resources remain
        allocated
```

During the idle period, the reserved capacity may not be used by that connection but is still allocated to it.

Therefore, circuit switching can be inefficient for **bursty traffic**, such as web browsing, where data arrives in bursts separated by idle periods.

Packet switching can use **statistical multiplexing**, allowing other users to utilize the shared capacity.

---

### Q4. A link has bandwidth 20 Mbps. A file is 10 MB. Ignoring all other delays, what is its transmission delay?

Given:

$$
R=20Mbps
$$

$$
L=10MB
$$

Convert MB to bits:

$$
10MB=10\times10^6\text{ bytes}
$$

Since:

$$
1\text{ byte}=8\text{ bits}
$$

$$
L=10\times10^6\times8
$$

$$
L=80\times10^6\text{ bits}
$$

Transmission delay:

$$
T_{trans}=\frac{L}{R}
$$

$$
=\frac{80\times10^6}{20\times10^6}
$$

$$
\boxed{T_{trans}=4s}
$$

### Answer: **4 seconds**

---

### Q5. A signal travels 3,000 km at 200,000 km/s. What is its propagation delay?

Given:

$$
d=3000km
$$

$$
v=200000km/s
$$

Propagation delay:

$$
T_{prop}=\frac{d}{v}
$$

$$
=\frac{3000}{200000}
$$

$$
=0.015s
$$

Convert to milliseconds:

$$
0.015\times1000=15ms
$$

### Answer:

$$
\boxed{15ms}
$$

---

### Q6. Which delay depends on data size: transmission delay or propagation delay?

**Answer:**

$$
\boxed{\text{Transmission delay}}
$$

Transmission delay is:

$$
T_{trans}=\frac{L}{R}
$$

where \(L\) is the amount of data in bits.

Therefore, increasing the file/packet size increases transmission delay.

Propagation delay is:

$$
T_{prop}=\frac{d}{v}
$$

It depends on:

* distance \(d\)
* propagation speed \(v\)

It does **not** depend on the amount of data being transmitted.

### Easy memory trick:

> **Transmission → Data size + bandwidth**

> **Propagation → Distance + signal speed**

---

### Q7. If the distance between two hosts doubles but bandwidth remains unchanged, which changes?

Options:

* Transmission delay
* Propagation delay
* Both
* Neither

**Answer:**

$$
\boxed{\text{Propagation delay}}
$$

Because:

$$
T_{prop}=\frac{d}{v}
$$

If distance doubles:

$$
d\rightarrow2d
$$

then:

$$
T_{prop}\rightarrow2T_{prop}
$$

But transmission delay is:

$$
T_{trans}=\frac{L}{R}
$$

Since neither file size \(L\) nor bandwidth \(R\) changed:

$$
T_{trans}=\text{unchanged}
$$

### Therefore:

> **Propagation delay doubles; transmission delay remains unchanged.**

---

### Q8. A user establishes a circuit but then remains completely idle for 20 seconds. Why can this be inefficient compared with packet switching?

**Answer:**

Circuit switching reserves resources for the established connection for its duration.

Suppose:

```text
Circuit established
       ↓
Data
       ↓
20 seconds idle
       ↓
More data
       ↓
Circuit released
```

During the 20-second idle period, the resources remain associated with that circuit even though the user isn't transmitting.

This can result in **underutilization of network capacity**.

In packet switching, resources are shared dynamically:

```text
User A ──┐
User B ──┼──→ Shared link
User C ──┘
```

When User A is idle, User B or User C can potentially use the available capacity.

Therefore:

> **Circuit switching can be inefficient for bursty traffic, whereas packet switching is generally more efficient because network resources are statistically shared.**

# ⭐ Most Important Formulas So Far

Keep these three formulas very clear:

### 1. Transmission Delay

$$
\boxed{T_{trans}=\frac{L}{R}}
$$

**Depends on:** data size and bandwidth.

---

### 2. Propagation Delay

$$
\boxed{T_{prop}=\frac{d}{v}}
$$

**Depends on:** distance and propagation speed.

---

### 3. Simplified Circuit-Switching Total Time

For the type of problem in your professor's PPT:

$$
\boxed{
T_{total}=T_{setup}+T_{prop}+T_{trans}
}
$$

But remember that **the exact end-to-end delay formula depends on the assumptions of the problem**—for example, whether propagation occurs during setup and whether acknowledgments/teardown are included.

## 🔥 One important distinction to remember

|                | Circuit Switching            | Datagram Switching      |
| -------------- | ---------------------------- | ----------------------- |
| Setup          | Required                     | Not required            |
| Path           | Established first            | Determined per packet   |
| Resources      | Reserved                     | Dynamically shared      |
| Delay          | More predictable after setup | Variable                |
| Bursty traffic | Less efficient               | Generally efficient     |
| Packets        | Follow established circuit   | Independently forwarded |
