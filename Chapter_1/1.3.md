# Part 3: Virtual Circuit Switching

Now we come to the **third switching technique** in your professor's chapter.

So far:

```text
                    Network Switching
                           │
             ┌─────────────┴─────────────┐
             │                           │
       Connectionless              Connection-oriented
             │                           │
       Datagram                    ┌──────┴──────┐
       Switching                   │             │
                              Circuit         Virtual
                              Switching       Circuit
```

The important thing about **Virtual Circuit (VC) switching** is that it combines ideas from both approaches.

---

# 1. Why do we need Virtual Circuits?

Let's recall the two techniques.

### Datagram switching

```text
P1 ──→ Path 1 ──→ B
P2 ──→ Path 2 ──→ B
P3 ──→ Path 1 ──→ B
```

Advantages:

* No connection setup
* Efficient sharing of network resources
* Good for bursty traffic

But:

* Packets may take different paths
* Variable delay
* Packets may arrive out of order
* Each packet needs destination information

---

### Circuit switching

```text
A ═══════════════════ B
      Dedicated
       circuit
```

Advantages:

* Established path
* Predictable behavior
* Resources can be reserved

But:

* Requires setup
* Resources can be wasted during idle periods
* Dedicated physical resources can be inefficient for bursty data

---

## Virtual circuit switching tries to combine useful ideas from both.

The basic idea is:

> **Establish a logical path before sending data, but carry the data using packets over shared physical network infrastructure.**

---

# 2. What is a Virtual Circuit?

A **virtual circuit** is a logical connection established between a source and destination through a packet-switched network.

It is called "virtual" because the path is **logical rather than necessarily being a physically dedicated circuit**.

Imagine:

```text
Physical network:

       R1 ───── R2
      /  \     /  \
     /    \   /    \
    A      R3       B
     \    /   \    /
      ───R4───────
```

A virtual circuit might establish:

```text
A → R1 → R2 → B
```

This becomes the logical path for that connection.

Other users can still use the same physical links.

---

# 3. Three Phases of Virtual Circuit Switching

Just like circuit switching, VC switching generally has three phases:

```text
             Virtual Circuit
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
    Setup        Transfer      Teardown
```

### Phase 1 — VC Setup

The network establishes a logical path.

```text
A → R1 → R2 → R3 → B
```

Each intermediate device establishes the appropriate VC state.

---

### Phase 2 — Data Transfer

Packets are sent along the established virtual circuit.

```text
P1 ───────────────→ B
P2 ───────────────→ B
P3 ───────────────→ B
```

The packets normally follow the same logical path.

---

### Phase 3 — Teardown

When communication finishes, the virtual circuit state is removed.

```text
VC established
      ↓
Data transfer
      ↓
VC released
```

---

# 4. The Most Important Concept: VC Identifier

This is where VC switching becomes technically interesting.

In datagram switching, a packet might contain:

```text
+---------------------+
| Destination Address |
+---------------------+
| Data                |
+---------------------+
```

Every router examines the destination address.

In virtual circuit switching, after setup, packets can carry a **Virtual Circuit Identifier (VCI)**.

For example:

```text
+-------------------+
| VCI = 17          |
+-------------------+
| Data              |
+-------------------+
```

The router can use:

$$
VCI = 17
$$

to determine the appropriate outgoing interface and next VC identifier.

---

# 5. Example of VCI Translation

Suppose:

```text
A ── R1 ── R2 ── B
```

During setup, the network might establish:

```text
A → R1 → R2 → B
```

and assign identifiers:

```text
A → R1 : VCI 10
R1 → R2: VCI 25
R2 → B : VCI 7
```

Notice something important:

> The VCI doesn't necessarily remain the same across every link.

A router can perform a mapping:

```text
Incoming
VCI 10
   │
   ↓
  R1
   │
   ↓
Outgoing
VCI 25
```

Then:

```text
R2:

Incoming VCI 25
       │
       ↓
Outgoing VCI 7
```

So the forwarding state can look like:

| Incoming Interface | Incoming VCI | Outgoing Interface | Outgoing VCI |
| ------------------ | -----------: | ------------------ | -----------: |
| 1                  |           10 | 2                  |           25 |
| 2                  |           25 | 3                  |            7 |

This is a **very important concept** for understanding VC networks.

---

# 6. Datagram vs Virtual Circuit

Let's compare the packet header.

### Datagram

Each packet carries the destination address.

```text
P1:
Destination = B

P2:
Destination = B

P3:
Destination = B
```

Each packet is independently forwarded.

---

### Virtual Circuit

Packets carry a VC identifier.

```text
P1:
VCI = 10

P2:
VCI = 10

P3:
VCI = 10
```

The network already knows:

```text
VCI 10 → established path
```

So forwarding can be simpler/faster than doing a full destination lookup at every hop, depending on the implementation.

---

# 7. Very Important: "Virtual" Does NOT Mean "No Path"

A common misunderstanding is:

> "Since it is virtual, packets can take any path."

❌ **That's not the intended idea.**

A virtual circuit establishes a **logical path**.

For example:

```text
A → R1 → R3 → R5 → B
```

After setup, packets belonging to that VC generally follow this logical path.

So:

```text
P1 → R1 → R3 → R5 → B
P2 → R1 → R3 → R5 → B
P3 → R1 → R3 → R5 → B
```

rather than independently selecting arbitrary routes.

---

# 8. Does a Virtual Circuit Reserve Physical Bandwidth?

This is where you need to be careful with the simplified explanation in your professor's PPT.

A virtual circuit establishes a **logical connection**, but it does **not necessarily reserve a dedicated physical link/bandwidth in the same way as traditional circuit switching**.

Think:

### Circuit switching

```text
Physical resources
════════════════════
Reserved for A → B
```

### Virtual circuit

```text
Shared physical infrastructure

A ──┐
B ──┼──── Shared links ────
C ──┘
```

The VC provides a logical path through the shared packet network.

Some VC technologies can provide resource guarantees or reservations, but **VC establishment itself should not automatically be equated with dedicated physical bandwidth**.

This distinction is important for higher-level networking questions.

---

# 9. Why Is VC Useful?

Suppose an organization has:

```text
Branch A ───── Internet/shared fiber ───── Branch B
```

They want:

* a logical connection
* packets to follow an established path
* ordered delivery behavior associated with the connection
* shared physical infrastructure

A virtual circuit can provide the logical connection without requiring a dedicated physical cable between A and B.

---

# 10. Example

Suppose:

```text
London ─ R1 ─ R2 ─ R3 ─ Tokyo
```

A virtual circuit is established:

```text
London
   │
   ↓
  R1
   │
   ↓
  R2
   │
   ↓
  R3
   │
   ↓
 Tokyo
```

Now suppose London sends:

```text
P1
P2
P3
P4
```

The packets belong to the same VC.

Conceptually:

```text
P1 ─┐
P2 ─┤
P3 ─┼──→ established logical path ──→ Tokyo
P4 ─┘
```

The physical links are still part of a shared network.

# 11. Comparison of All Three Techniques

This is something you should **definitely know for your exam**.

| Property                      | Circuit Switching                 | Datagram Switching                  | Virtual Circuit                           |
| ----------------------------- | --------------------------------- | ----------------------------------- | ----------------------------------------- |
| Connection setup              | Yes                               | No                                  | Yes                                       |
| Connection type               | Dedicated circuit                 | Connectionless                      | Logical connection                        |
| Physical resource reservation | Typically yes                     | No                                  | Not inherently                            |
| Packet concept                | Continuous circuit/data stream    | Independent packets                 | Packets belonging to a VC                 |
| Path                          | Established                       | Can vary                            | Established logical path                  |
| Identifier                    | Circuit/connection state          | Destination address                 | VCI/label                                 |
| Forwarding                    | Based on circuit                  | Destination lookup                  | VC/label lookup                           |
| Bursty traffic                | Less efficient                    | Efficient                           | Generally can share resources efficiently |
| Failure handling              | Circuit may need re-establishment | Packets can potentially be rerouted | VC may need re-establishment/rerouting    |
| Typical example               | Traditional telephone networks    | IP                                  | ATM, Frame Relay                          |

---

# 12. The Key Difference

Here's the simplest way to remember all three:

### Circuit Switching

> **"Reserve a circuit first."**

```text
A ═════════════ B
```

### Datagram Switching

> **"Send packets independently."**

```text
P1 → Path A
P2 → Path B
P3 → Path A
```

### Virtual Circuit

> **"Establish a logical path first, then send packets through it."**

```text
A ──→ R1 ──→ R2 ──→ B
     Logical VC
```

---

# 13. One Important Exam Trap

Suppose the question says:

> "Packets are guaranteed to follow the same path because a connection was established."

You should **not immediately answer circuit switching**.

It could be:

* Circuit switching
* Virtual circuit switching

You need to inspect the rest of the question.

If it says:

> **Dedicated physical resources are reserved**

→ Circuit switching.

If it says:

> **Logical connection over shared packet-switched infrastructure**

→ Virtual circuit.

---

# 14. Another Exam Trap

### Statement:

> "Virtual circuit switching is the same as circuit switching."

❌ **False.**

The major distinction is:

```text
Circuit:
Dedicated circuit/resources

Virtual Circuit:
Logical path over packet-switched/shared infrastructure
```

A VC can provide connection-oriented behavior without necessarily dedicating physical resources in the same manner as circuit switching.

---

# 15. Your Professor's Bank Example

Your PPT says:

> A bank wants predictable sequential communication but needs to use existing shared fiber infrastructure.

The intended answer is:

$$
\boxed{\text{Virtual Circuit Switching}}
$$

Why?

Because the bank can establish a **logical path** while still using the shared underlying network.

Conceptually:

```text
Branch A
   │
   ↓
Shared network
   │
   ↓
Branch B

Logical VC:
A ═══════════ B
```

The physical network remains shared.

---

# 16. One More Important Point: Ordered Delivery

Because packets belonging to a VC follow the same logical path, they generally arrive in the same order in which they were sent, assuming no unusual lower-layer reordering behavior.

For example:

```text
Sender:

P1 → P2 → P3 → P4

VC path:

P1 ─────────→
P2 ─────────→
P3 ─────────→
P4 ─────────→

Receiver:

P1 → P2 → P3 → P4
```

This contrasts with datagram switching, where different paths can produce different delays:

```text
P1 ────────→ 20 ms
P2 ────→     10 ms
P3 ───────→  15 ms

Arrival:
P2 → P3 → P1
```

So virtual circuits make **in-order delivery easier to maintain**, although don't interpret VC establishment alone as a universal guarantee of every end-to-end service property.

# 🧠 Final Mental Model

Imagine three different postal systems.

### Datagram

Every parcel says:

> "Deliver this to Mumbai."

Every parcel is routed independently.

```text
Parcel 1 → Route A

Parcel 3 → Route A
```

### Circuit

Before sending anything:

> "Reserve this road from Delhi to Mumbai for our communication."

```text
Delhi ═════════════ Mumbai
```

### Virtual Circuit

Before sending:

> "Create a logical route from Delhi to Mumbai."

Then all parcels carry something like:

```text
VCI = 42
```

and the network knows:

```text
VCI 42 → this established logical path
```

while the underlying roads can still be shared with other traffic.

# CS 606T — Virtual Circuit Switching: Answers

### Q1. What is a virtual circuit?

**Answer:**

A **virtual circuit (VC)** is a **logical connection** established between a source and destination through a packet-switched network before data transmission begins.

Once established, packets belonging to that connection are forwarded along the established logical path.

```text
A → R1 → R2 → R3 → B
    ═════════════
     Logical VC
```

**Exam definition:**

> Virtual circuit switching is a connection-oriented packet-switching technique in which a logical path is established between the source and destination before data transmission.

---

### Q2. What are the three phases of virtual circuit switching?

**Answer:**

There are three phases:

1. **VC Setup**
2. **Data Transfer**
3. **VC Teardown**

```text
Setup
  ↓
Data Transfer
  ↓
Teardown
```

During setup, the network establishes the logical path and VC state.

During data transfer, packets use the established VC.

During teardown, the VC state is removed.

---

### Q3. Why is a virtual circuit called "virtual"?

**Answer:**

It is called **virtual** because the connection is a **logical path**, not necessarily a dedicated physical circuit.

The underlying physical links can be shared by multiple users.

```text
        Shared physical network
A ───────┐
B ───────┼──────── Network ────────
C ───────┘

Logical VC:
A ═════════════════════════ B
```

Therefore:

> **Virtual = logically established connection, not necessarily a physically dedicated connection.**

---

### Q4. What is a VCI?

**Answer:**

**VCI (Virtual Circuit Identifier)** is an identifier used to identify a particular virtual circuit.

After the VC is established, packets can carry the VCI instead of requiring the complete destination address to make the forwarding decision.

Example:

```text
+----------------+
| VCI = 17       |
+----------------+
| Data           |
+----------------+
```

A router can use:

$$
VCI=17
$$

to determine the appropriate outgoing interface and next VC identifier.

---

### Q5. Can the VCI remain different on different links?

**Answer:**

**Yes.**

A VC identifier is typically **local to a link/interface**, so a router can translate an incoming VCI into a different outgoing VCI.

Example:

```text
A ── R1 ── R2 ── B

A → R1 : VCI 10
R1 → R2: VCI 25
R2 → B : VCI 7
```

At R1:

```text
Incoming VCI 10
       ↓
      R1
       ↓
Outgoing VCI 25
```

At R2:

```text
Incoming VCI 25
       ↓
      R2
       ↓
Outgoing VCI 7
```

A forwarding table might contain:

| Incoming Interface | Incoming VCI | Outgoing Interface | Outgoing VCI |
| ------------------ | -----------: | ------------------ | -----------: |
| 1                  |           10 | 2                  |           25 |
| 2                  |           25 | 3                  |            7 |

**Important exam point:**

> VCI values need not be globally unique; they can have **local significance**.

---

### Q6. Does establishing a virtual circuit necessarily mean that dedicated physical bandwidth is reserved?

**Answer:**

**No.**

Establishing a virtual circuit primarily establishes a **logical path and forwarding state**.

The underlying physical network can still be shared by multiple connections.

```text
Physical network:
────────────────────────────
 VC1 ──┐
 VC2 ──┼── Shared links
 VC3 ──┘
────────────────────────────
```

This is an important difference from traditional circuit switching, where resources are typically reserved for the duration of the circuit.

**Exam point:**

> A VC provides a logical connection; it should not automatically be interpreted as a dedicated physical circuit.

---

### Q7. In datagram switching, packets contain destination information. What does a VC packet use for forwarding after setup?

**Answer:**

After VC setup, the packet generally uses a **Virtual Circuit Identifier (VCI)** or an equivalent connection/label identifier.

For example:

```text
Packet:

+----------------+
| VCI = 25       |
+----------------+
| Data           |
+----------------+
```

The router looks up the VCI in its VC forwarding table:

```text
VCI 25
  ↓
Outgoing interface + outgoing VCI
```

Therefore:

$$
\boxed{\text{Datagram → Destination information}}
$$

$$
\boxed{\text{Virtual Circuit → VCI/connection identifier}}
$$

---

### Q8. Which technique is represented by Setup → Data → Teardown with a dedicated physical circuit?

**Answer:**

$$
\boxed{\text{Circuit Switching}}
$$

Circuit switching establishes a dedicated circuit before data transfer.

```text
Setup
  ↓
════════════════
Dedicated path
════════════════
  ↓
Data Transfer
  ↓
Teardown
```

**Key clue:**

> **Dedicated physical resources/circuit**

→ Circuit Switching.

---

### Q9. Which technique is represented by Setup → Data → Teardown with a logical path over shared packet-switched infrastructure?

**Answer:**

$$
\boxed{\text{Virtual Circuit Switching}}
$$

The key distinction is:

```text
Circuit switching:
Dedicated physical circuit

Virtual circuit:
Logical connection over shared packet network
```

**Key clue:**

> **Logical path + shared packet-switched infrastructure**

→ Virtual Circuit Switching.

---

### Q10. A company wants connection-oriented communication but does not want to dedicate a physical link between every pair of branches. Which technique does this description point toward, and why?

**Answer:**

$$
\boxed{\text{Virtual Circuit Switching}}
$$

A virtual circuit provides a **connection-oriented logical path** while allowing the underlying physical network to be shared by multiple users/connections.

Example:

```text
Branch A ──┐
           │
           ↓
      Shared Network
           │
           ↓
Branch B ──┘

Logical VC:
A ═════════════ B
```

Therefore, the company can obtain a logical connection without requiring a dedicated physical link between every pair of branches.
